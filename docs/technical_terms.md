# 핵심 용어 및 기법 정리

## 1. Bhattacharyya Distance (바타차야 거리)
- **정의**: 두 확률분포가 얼마나 겹치는지 측정하는 거리. 분포가 완전히 같으면 0, 완전히 다르면 1에 가깝습니다.
- **프로젝트에서의 사용**: ReID 갤러리에 저장된 5개의 band 특징과 현재 트랙의 특징 간 유사도를 계산할 때 사용합니다. 거리가 작을수록 같은 차량일 가능성이 높습니다.
- **장점**: L2 거리보다 분포 모양(색상 밴드, 텍스처 등)을 더 잘 반영하고, 정규화된 확률기반 비교라 조명 변화에도 안정적입니다.

## 2. Hungarian Algorithm (헝가리안 알고리즘)
- **정의**: 매칭 비용 행렬을 기반으로 최적의 1:1 매칭을 찾는 조합 최적화 알고리즘. Assignment 문제(작업-작업자 배정)를 해결합니다.
- **프로젝트에서의 사용**: YOLO11 + ByteTrack 추적 내부에서, 새 감지 결과와 이전 프레임 트랙을 연결할 때 사용됩니다. 비용 행렬은 IoU(박스 겹침)나 속도 모델에 기반합니다.
- **특징**: 한 번의 연산으로 글로벌 최적 매칭을 구하므로, 단순 탐욕 매칭보다 중첩된 차량이나 교차 상황에서 ID 유지가 잘 됩니다.

## 3. Activation Function과의 유사성?
- 헝가리안 알고리즘은 활성화 함수가 아니라 **최적화 알고리즘**입니다. 다만 "입력(비용 행렬)을 정규화된 결과(최적 매칭)로 변환한다"는 점에서, 신경망의 활성화 함수가 실수 값을 특정 범위로 변환하는 역할과 추상적 유사성이 있을 뿐입니다. 실제 동작은 완전히 다릅니다.

## 4. Re-ID 5-Band Feature
- **구성**: 선택된 차량 crop에서 색상/텍스처 정보를 5개 밴드로 나눠 저장합니다. 각 밴드는 상하/중앙/등 부분 등 서로 다른 영역을 담당합니다.
- **목적**: 부분 가림이나 조명 변화에도 안정적으로 비교하기 위해, 전체 이미지를 한 번에 비교하는 대신 여러 밴드의 평균 거리와 개별 밴드 거리를 모두 기록합니다.

## 5. ConsecutiveMatchValidator
- **역할**: Bhattacharyya distance가 임계값을 넘더라도, 같은 차량으로 확정하려면 연속 N프레임(기본 3프레임) 동안 조건을 만족해야 합니다.
- **효과**: 임시 노이즈나 유사 차량으로 인한 오탐을 줄이고, 실제 handover 시에만 선택 ID를 갱신합니다.

## 6. Adaptive Threshold
- **정의**: ReIDBank가 저장한 갤러리의 출처(같은 세그먼트인지, 다른 카메라인지)에 맞춰 임계값을 동적으로 조정하는 방법입니다.
- **이점**: 같은 카메라에서는 더 엄격하게, 다른 카메라에서는 조금 느슨하게 기준을 적용해 False Positive/False Negative를 균형 있게 줄입니다.

## 7. TrackHistory.get_history()
- **정의**: 특정 트랙 ID에 대해 최근 프레임들의 crop·bbox·frame_idx를 `deque` 형태로 저장해 두었다가 리스트로 반환하는 함수입니다.
- **용도**: 사용자가 클릭했는데 현재 프레임에 박스가 없을 때, 과거 15프레임 이내 히스토리에서 가장 가까운 위치를 찾아 선택 보조로 활용합니다. 또한 히스토리 crop을 ReID 갤러리 초기화에 재사용할 수 있습니다.

## 8. find_closest_track_in_history()
- **정의**: `TrackHistory`에 쌓여 있는 여러 트랙을 훑어, 주어진 클릭 좌표와 가장 가까운 히스토리 샘플을 찾아 ID와 거리, 프레임 인덱스를 반환하는 함수입니다.
- **의미**: 실시간 프레임에서 박스를 놓쳤을 때도 최근 히스토리로 보정해 사용자의 클릭 경험을 개선하고, 선택 실패 로그를 줄입니다.

## 9. cv2.calcHist (OpenCV 히스토그램)
- **정의**: OpenCV에서 이미지의 픽셀 분포를 계산하는 함수로, 특정 채널(Hue/Saturation/Value 등)에 대한 빈도 히스토그램을 만듭니다.
- **프로젝트에서의 사용**: `reid/feature_extractor.py`의 `_extract_color_features`에서 HSV 색상 히스토그램을 계산해 `histogram_h/s/v`로 저장합니다.
- **의미**: 색상 분포를 정규화된 벡터로 표현해 다양한 조명·각도에서도 차량의 주요 색상 특성을 비교할 수 있게 해 줍니다.

## 10. HSV 색공간
- **정의**: Hue(색상), Saturation(채도), Value(명도)로 색을 표현하는 모델입니다. Hue는 0~180° 범위에서 빨강~초록~파랑을 나타내고, Saturation은 색의 선명도, Value는 밝기를 의미합니다.
- **사용 이유**: BGR(RGB)보다 조명 변화에 덜 민감해 특정 색상 영역을 마스크하거나 히스토그램으로 비교하기에 적합합니다. 예를 들어 `cv2.inRange(hsv, lower, upper)`로 빨간색 차량을 안정적으로 추출할 수 있습니다.

## 11. HSV 히스토그램과 Bhattacharyya 거리의 연결
- **저장 방식**: `reid/feature_extractor.py`에서 계산한 Hue/Saturation/Value 히스토그램은 각 채널별 bin을 전체 픽셀 수로 나눠 **합이 1이 되는 확률분포**로 정규화한 뒤, ReIDBank에 밴드 단위로 저장합니다.
- **거리 사용 이유**: 이렇게 정규화된 벡터는 “각 색상 구간에 속한 비율”을 나타내므로, 두 분포가 얼마나 겹치는지 측정하는 Bhattacharyya distance가 적합합니다. 값이 0에 가까울수록 색상 분포가 비슷해 동일 차량일 확률이 높고, 1에 가까울수록 다른 차량일 가능성이 큽니다.
